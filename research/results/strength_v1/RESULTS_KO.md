# Scaffold 강도 조절 실험 (strength_v1): A 강도-LM, B 노출 빈도별 loss, C 오타 강건성

2026-10-13 · source `48f7d85` · jelly H100 GPU 2, 3 · run root `~/jihyun_scaffold/runs/strength`

**결론: scaffold 판정을 강하게 할수록(c = 4, 8) LM BPB가 좋아진다. seed 5개 모두 같은 방향이고, 문서 bootstrap 95% CI도 0을 포함하지 않는다.
압축은 오히려 나빠지는데 LM은 좋아진다. 원래 Scaffold(c = 1)는 BPE와 차이가 없다(infer_v1과 일치).**
지금까지 이 프로젝트에서 노이즈를 넘은 첫 양성 결과다.

## 설정

- **tokenizer:** 토큰 x는 `f(x) < c · f(Qhead)`이면 scaffold가 된다(vocab에서 숨겨지고, 인코딩 때 철거).
  c = 1이 Scaffold-BPE, c = 0은 일반 BPE다(merge 수를 K에 맞춤).
  모든 arm은 보이는 vocab K = 32,767(+EOS)로 같고, 같은 trainer(`scaffold_margin.bpe.train_bpe`, global 규칙)와
  같은 WikiText-103 train word counts(GPT-2 pretokenizer)를 쓴다.
- **LM:** 42.5M, seq 1024, batch 131K tokens, 2 epoch, lr 6e-4, bf16 + compile, micro batch 64(gradient accumulation 2).
  run마다 초기화 seed와 데이터 순서 seed를 같게 했다. seed는 c ∈ {0, 1, 4, 8}에 5개, c ∈ {0.5, 2}에 3개다.
- **비교 주의:** infer_v1 모델은 팀 tokenizer(Wikipedia 1B로 학습)와 fp16을 썼다.
  이번 실험은 WikiText train으로 tokenizer를 학습해서 압축률과 BPB 절대값이 다르다(BPB 약 1.08 vs 1.09).
  arm 간 비교는 모두 이번 실험 안에서만 했다.

## A. 강도별 결과

| c | 숨긴 토큰 수 | merge 수 | test 토큰 (BPE 대비) | 학습 노출 <100 토큰 | test BPB (평균 ± sd) | seed 수 |
|---|---:|---:|---:|---:|---:|---:|
| 0 (BPE) | 0 | 32,511 | 271,659 | 1,760 | 1.08681 ± 0.0024 | 5 |
| 0.5 | 2,232 | 34,743 | −0.36% | 94 | 1.08599 ± 0.0036 | 3 |
| 1 (Scaffold) | 3,926 | 36,437 | −0.45% | 93 | 1.08777 ± 0.0031 | 5 |
| 2 | 26,891 | 59,402 | +0.02% | 91 | 1.08440 ± 0.0032 | 3 |
| 4 | 58,659 | 91,170 | +0.25% | 91 | 1.08389 ± 0.0021 | 5 |
| 8 | 101,041 | 133,552 | +0.52% | 89 | 1.08312 ± 0.0023 | 5 |

같은 seed끼리 짝지은 차이와 문서 bootstrap 95% CI:

| 비교 | 평균 차이 | seed별 차이 | 문서 CI | 판단 |
|---|---:|---|---|---|
| c1 − c0 | +0.0010 | +0.0036, −0.0015, +0.0021, +0.0013, −0.0007 | [−0.0006, +0.0024] | 차이 없음 |
| c4 − c0 | −0.0029 | −0.0003, −0.0027, −0.0069, −0.0017, −0.0032 | [−0.0057, −0.0008] | **c4가 좋음 (5/5 seed)** |
| c8 − c0 | −0.0037 | −0.0051, −0.0034, −0.0026, −0.0015, −0.0058 | [−0.0065, −0.0016] | **c8이 좋음 (5/5 seed)** |
| c8 − c1 | −0.0047 | −0.0088, −0.0019, −0.0047, −0.0029, −0.0051 | [−0.0067, −0.0028] | **c8이 좋음 (5/5 seed)** |
| c2 − c0 | −0.0020 | +0.0014, −0.0037, −0.0039 (3 seed) | [−0.0042, −0.0001] | 경계선 |

- 효과 크기는 BPB 약 0.3~0.4%다. seed sd(0.002~0.003)와 비슷하지만 5개 seed에서 방향이 모두 같다.
- 압축률과 LM 품질이 반대로 움직인다. c = 8은 BPE보다 토큰이 0.52% 많지만 BPB는 0.0037 낮다.
  "압축이 좋을수록 LM이 좋다"는 가정에 대한 반례로, survey §7.2.2에 정리된 상관이 약하다는 보고들과 같은 방향이다.
- 저노출 토큰 제거(Scaffold의 원래 동기)는 이미 c = 0.5에서 거의 끝난다(1,760 → 94).
  그런데 LM 이득은 c ≥ 2에서야 나타난다. 그래서 "드물게 학습된 토큰 제거"만으로는 이득이 설명되지 않는다.

## 왜 좋아지나: vocab 구성 변화 (tokenizer 자체 지표, 학습 노이즈 없음)

| c | 단어 내부 토큰 비율 (vocab) | vocab 평균 길이 (바이트) | 본문 평균 토큰 길이 (바이트) | test에서 쓰인 토큰 종류 | Rényi 효율 (α=2.5) |
|---|---:|---:|---:|---:|---:|
| 0 | 20.5% | 6.58 | 4.740 | 18,396 | 0.4169 |
| 1 | 16.8% | 6.76 | 4.761 | 18,561 | 0.4162 |
| 4 | 10.4% | 7.18 | 4.728 | 17,753 | 0.4173 |
| 8 | 7.8% | 7.36 | 4.715 | 17,350 | 0.4177 |

- c가 커질수록 단어 중간 조각(`ers`, `ock` 같은)이 vocab에서 빠지고 통단어(단어 시작 토큰)로 채워진다.
- vocab에 없는 단어는 더 작은 조각으로 쪼개져서 압축은 나빠진다. 대신 남은 조각이 더 많은 단어에서 재사용된다.
  test에서 쓰이는 토큰 종류 수가 줄어드는 것(18.4K → 17.4K)이 이 해석과 맞는다.
- Rényi 효율도 c = 1 이후 단조롭게 오르지만 차이가 작다(0.4162 → 0.4177). 이것만으로 효과를 설명하지는 않는다.
- 이 해석은 상관관계다. 인과(어떤 성질이 BPB를 낮추는지)는 이번 실험으로 분리하지 않았다.

## B. 학습 노출 빈도별 loss (seed 0~2, test)

target 토큰이 학습에서 얼마나 자주 나왔는지 구간별로 나눈 bits/byte(괄호는 test 바이트 비중):

| c | 100~1K | 1K~10K | 10K~100K | 100K~1M | ≥1M |
|---|---|---|---|---|---|
| 0 | 1.38 (12.3%) | 1.16 (33.1%) | 1.10 (26.5%) | 0.99 (12.3%) | 0.73 (15.8%) |
| 1 | 1.40 (13.0%) | 1.16 (32.7%) | 1.11 (26.4%) | 0.98 (12.2%) | 0.73 (15.8%) |
| 8 | 1.35 (12.3%) | 1.14 (32.3%) | 1.13 (27.4%) | 0.99 (12.2%) | 0.74 (15.8%) |

- BPE에는 노출 100회 미만 토큰이 test 바이트의 0.07%를 차지하고, bits/byte는 2.29다. Scaffold 계열에서는 이 구간이 사실상 0%다.
  다만 전체 BPB 기여는 약 0.0006으로 작다.
- c = 8의 이득은 중간 빈도(100~10K) 토큰 구간에 몰려 있다. 대신 10K~100K 구간은 오히려 약간 나쁘다.
  구간마다 토큰 구성이 tokenizer별로 다르므로 구간 간 직접 비교는 참고용이다.

- 강도(c)는 오타 강건성에 영향이 없다. 오타 15%에서 c = 8의 이득은 사라진다(1.5940 = BPE).
- Mix 학습만 증가분이 작다(15%에서 −0.013). 하지만 clean에서 잃은 0.018을 다 메우지는 못해서, 오타 15%에서도 절대값은 Mix가 가장 나쁘다.

## 범위와 주의

- 규모는 42.5M 모델, 2 epoch, WikiText-103, 32K 하나다. 더 큰 모델·데이터에서 유지되는지는 모른다.
- c = 0.5와 2는 seed가 3개뿐이다. c를 여러 개 비교했으므로 다중비교 보정은 하지 않았다.
  다만 c = 4와 c = 8은 각각 5/5 seed가 같은 방향이고, c가 커질수록 단조로운 경향을 보인다.
- 다운스트림 과제와 다른 vocab 크기에서는 측정하지 않았다.
